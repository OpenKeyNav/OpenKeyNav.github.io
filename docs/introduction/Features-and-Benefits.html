Features and Benefits

OpenKeyNav provides optional keyboard interactions for websites and web applications. Developers can use it when an interface contains many targets, complex pointer interactions, or drag-and-drop behavior. Each team must evaluate the result in its host application with representative users.

Features​

  1. Dynamic Label Overlay:

    • Behavior: OpenKeyNav generates and displays typeable labels over detected targets when a user requests them.
    • Possible result: Users can select a distant target directly instead of traversing every preceding control. Developers must still provide programmatic accessible names.

  2. Customizable Key Bindings:

    • Behavior: Developers configure activation keys for selecting targets, scrolling, and moving items.
    • Possible result: Teams can adapt the interaction to the host application. Developers must test the configuration against application, browser, operating system, and assistive technology shortcuts.

  3. On-Demand Keyboard Shortcuts:

    • Behavior: OpenKeyNav generates shortcuts and presents them while a user keeps the relevant mode active.
    • Possible result: Users do not need a permanent shortcut for every target. Teams must evaluate discoverability, learnability, and preference with representative users.

  4. Comprehensive Navigation Options:

    • Behavior: OpenKeyNav supports selection, scrolling, movement, and configured drag-and-drop operations from a keyboard.
    • Possible result: Developers can provide an alternate keyboard path for pointer-driven interactions. They must still provide correct semantics, state, instructions, and focus behavior.

  5. Framework-Agnostic Integration:

    • Behavior: OpenKeyNav runs in the browser with plain HTML and JavaScript frameworks.
    • Possible result: Teams can use the same interaction model in different application stacks. Test every browser, device, framework, input method, and assistive technology in the product support policy.

  6. Keyboard Accessibility Diagnostics:

    • Behavior: OpenKeyNav flags elements that its debug heuristics detect as pointer-clickable and unfocusable.
    • Possible result: Teams can find candidates for manual review. Developers must still evaluate every element and task against applicable requirements.

Benefits​

  • More direct keyboard interaction: Typeable labels can provide a faster alternate path to targets in interfaces with many controls.

  • An alternative to pointer-only actions: Configured movement and drag-and-drop modes can make complex application tasks available from a keyboard.

  • Earlier discovery of potential barriers: Debug output can focus a developer's manual investigation on elements that may have missing keyboard behavior.

  • Community review and adaptation: Adopters and contributors can inspect, test, discuss, and improve OpenKeyNav's open-source implementation.

Teams should verify each potential benefit with representative users. Keep OpenKeyNav optional and discoverable. Preserve standard Tab, arrow-key, Enter, Space, and Escape behavior.

Who may benefit​

People use keyboard access for different reasons:

  1. People with Motor Disabilities:

    • People who have difficulty using a mouse due to arthritis, carpal tunnel syndrome, muscular dystrophy, or other physical disabilities may benefit from being able to navigate and interact with web content using a keyboard.

  2. People with Repetitive Strain Injuries (RSIs):

    • Those who suffer from repetitive strain injuries or other conditions that make using a mouse painful or difficult can benefit from keyboard shortcuts and navigation to reduce strain.

  3. Users of Assistive Technologies:

    • People who use switch devices, voice input, screen readers, or other assistive technologies often depend on keyboard-operable functionality. Teams must test each technology with OpenKeyNav. Developers must still provide semantic markup and accessible names.

  4. Power Users:

    • People who prefer using a keyboard for efficiency, such as developers and data-entry professionals, may use shortcuts to streamline repeated workflows.

  5. Situational Impairments:

    • Users with temporary injuries and people working without practical space for a mouse also benefit from keyboard accessibility.

  6. People with Visual Impairments:

    • Screen reader users and some people with low vision rely on predictable keyboard operation and visible focus. OpenKeyNav can provide an additional route to targets. Developers still need to provide focus visibility, meaningful focus order, accessible names, and screen reader testing.

  7. Older Adults:

    • Older adults who find it challenging to use a mouse due to tremors or other age-related conditions may benefit from a keyboard option.

  8. Cognitive Impairments:

    • Some users with cognitive disabilities may prefer visible, on-demand prompts. Other users may find a custom mode harder to learn. Use clear instructions and test the interaction with intended users.

People within each group have different preferences. Preserve native and conventional operation, allow users to turn the enhancement on and off, and include disabled people in usability testing.

Relationship to standards and law​

OpenKeyNav can help teams implement keyboard access related to WCAG 2.2 Success Criterion 2.1.1, Keyboard. Its opt-in shortcut mode can support work on Success Criterion 2.1.4, Character Key Shortcuts. Developers remain responsible for semantics, accessible names, focus order, visible focus, status communication, and error handling.

W3C evaluates conformance for complete pages and processes against all applicable requirements. Organizations must determine which laws and procurement standards apply to their products. Ask qualified counsel to review legal-compliance decisions.
